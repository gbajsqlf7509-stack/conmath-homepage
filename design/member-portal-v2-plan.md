# 콘매쓰 회원가입 2차 개편 · 개발 준비안 (미배포)

## 이번에 확정한 입력 항목

- **학부모:** 아이디, 비밀번호, **아이 이름**. 학부모 실명·전화번호·이메일·주소는 받지 않음.
- **협력학원 원장:** 아이디, 비밀번호, **학원명·학원 주소**. 개인 성명·전화번호·이메일은 받지 않음.
- **관리자:** 기존 별도 관리자 계정 유지. 공개 회원가입으로 관리자 역할 부여 금지.
- 신규 회원은 모두 `pending`; 관리자가 검토해 `approved` 또는 `rejected`로 처리.
- 가입 시 학생의 성적·진단·건강 정보·사진·상담 기록을 요청하지 않음.

## Supabase Auth 아이디 방식

현재 Supabase Auth 비밀번호 로그인은 이메일 또는 전화번호 기반이다. 일반 회원 입력창에서는 **아이디만** 받아, 내부에서는 `<정규화한 아이디>@accounts.conmath.kr` 형식의 **인증용 식별자**로 변환한다. 실제 이메일을 수집하지 않는다. 관리자 계정은 기존 이메일 로그인을 그대로 사용한다.

- 사용자 ID 규칙: **영문 소문자로 시작하는 4~20자**, 나머지는 소문자·숫자·밑줄(`_`). 대소문자 입력은 소문자로 정규화.
- `admin`, `administrator`, `support`, `system`, `root` 예약어 사용 불가.
- 인증용 주소를 실제 이메일 주소로 오해하여 확인/비밀번호 재설정 메일을 보내면 안 됨.
- **필수 선행 작업:** Supabase Authentication의 **Confirm email OFF** 확인 및 서버 적용. 이것이 꺼져 있지 않으면 내부 식별자에 메일이 전송될 수 있고 가입 완료도 안 됨.
- 사용자가 비밀번호를 잊으면 이메일·전화번호가 없어 자동 재설정할 수 없음. **관리자 본인확인 후 재설정** 절차를 별도로 마련해야 함. 아이 이름만으로 본인 확인 금지.
- 인증 API의 비밀번호 로그인 rate limiting 및 CAPTCHA 등 남용 방지 별도 검토.
- 사용자용 게시판, 예약, 관리자 정보에 내부 인증용 이메일을 표시하지 않음.

## 데이터베이스 준비

- `member_login_ids`: 인증 사용자와 사람이 기억하는 아이디 1:1 매핑 (UNIQUE). 본인과 관리자만 SELECT.
- `parent_children`: 학부모 계정에 처음 등록한 아이 이름 저장. 같은 회원이 나중에 여러 자녀를 연결할 수 있도록 별도 테이블. 본인과 관리자만 SELECT.
- `member_profiles`: 기존 회원 승인, 제휴학원 이름·주소 보관. 로그인용 내부 이메일만 Auth에서 사용.
- 신규 가입은 `auth.users` 트리거가 DB 내 가입 프로필/아이디/아이 이름을 원자적으로 생성. **user_metadata 값으로 관리자 권한 부여 금지**.
- 코드 초안: `design/username-child-schema-DRAFT.sql`. **아직 실제 Supabase에 적용하지 않음**. 운영 데이터베이스에 즉시 적용하면 현재 이메일 기반 로그인 사용자와 충돌할 수 있으므로 이전 테스트 후 적용.

## 원생 엑셀을 받은 뒤

1. 파일의 학생 이름·학년 등 필요한 항목을 사전에 검토하고 최소한으로 가져온다.
2. 가져온 학생 기록에는 새 내부 학생 ID를 발급한다. 기존 회원가입 시 입력한 아이 이름과 **일치한다는 이유만으로 계정을 자동 연결하지 않는다**.
3. 관리자가 실제 보호자 관계를 확인한 뒤 `parent_children.child_id` ↔ 실제 원생 ID를 연결한다.
4. 계정이 승인됐다는 이유만으로 성적·상담 정보가 열리는 것은 아니다. **검증된 원생 관계와 필요한 동의**가 충족돼야 접근한다.
5. 같은 이름, 형제자매, 보호자 복수인 경우를 지원하는 별도의 관계 테이블을 도입한다.

## SNS 형태의 학습 소통 · 설계 메모 (아직 미구현)

- 기본은 **아이별로 해당 보호자와 허가된 교사/관리자만 볼 수 있는 비공개 소통방**. 공개 피드나 다른 학부모에게 공개하는 방식은 기본값이 아님.
- 이후 `discussion_threads`(학생별 비공개 스레드), `discussion_messages`(작성자·본문·시간), `thread_members`(검증된 접근 권한) 설계.
- 사용자에게 보이는 글, 자료, 사진은 별도 접근 통제와 운영 방침이 확보될 때까지 업로드 기능 제공하지 않음.
- 아이의 상담·학습 과정에서 민감한 내용이 생길 수 있으므로 보존 기간, 삭제 권한, 교사 퇴사 시 접근 해제, 미성년자 개인정보 및 필요한 보호자 동의를 검토해야 함.
- 현재 학부모 마이페이지에는 **준비 중** 표시만 추가. 데이터 전송·메시지 발행 기능은 없음.
